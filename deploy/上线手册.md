# 花溪旅行 · 正式上线手册（从零到可用）

> 适用：把当前项目部署到公网，让**体验版/正式版小程序**能正常使用。
> 配套自检：`python travel-api/scripts/preflight_release.py --strict`（每完成一步跑一次，FAIL 归零才算能提审）。

---

## 0. 先认清：上线需要哪些"外部资源"

代码已经写好，但下面这些**必须你去办**，代码无法代办：

| # | 要买/要办 | 大概成本 | 耗时 | 备注 |
|---|---|---|---|---|
| 1 | 云服务器（2C2G 起，Ubuntu 22.04） | 学生机约 ¥100/年，普通约 ¥300+/年 | 即时 | 必须**中国内地**节点 |
| 2 | 域名（如 `your-domain.cn`） | ¥30–60/年 | 即时 | 需要实名 |
| 3 | **ICP 备案**（域名） | 免费 | **7–20 天** | 备案期间不能对外提供 Web 服务 |
| 4 | **小程序备案**（2023-09 起强制） | 免费 | 3–20 天 | 不做无法发布 |
| 5 | SSL 证书 | 免费（Let's Encrypt） | 10 分钟 | 脚本里已给命令 |
| 6 | 微信小程序真实 AppID + 类目/隐私指引 | 免费（企业主体需认证 ¥300/年，个人主体可先不认证） | 1–3 天 | 类目：旅游 → 旅游信息查询 |

> **个人主体**也能发布「旅游信息查询」类小程序，但不能有交易功能——本项目本来就不含预订/支付，符合要求。

## 1. 服务器初始化（一次性）

```bash
# 用 root 登录服务器后
apt update && apt -y upgrade
apt -y install python3.11 python3.11-venv python3.11-dev build-essential \
               mysql-server nginx git curl ufw

# 建运行用户与目录
useradd -m -s /bin/bash travel || true
mkdir -p /srv/travel /var/www/certbot
chown -R travel:travel /srv/travel

# 防火墙：只放 22/80/443，8000 不对公网开放
ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp && ufw --force enable
```

MySQL 安全初始化（设置 root 密码、删除匿名用户）：

```bash
mysql_secure_installation
```

## 2. 上传代码与静态资源（在 Windows 本地）

```powershell
# 1) 先构建两个前端（产物由 Nginx 托管）
cd travel-portal ; npm run build ; cd ..
cd travel-web    ; npm run build ; cd ..

# 2) 同步到服务器（改成你的 IP / 域名）
powershell -ExecutionPolicy Bypass -File deploy\scripts\upload.ps1 -Server "root@1.2.3.4"
```

> `upload.ps1` 会排掉 `.venv`、`__pycache__`、`.env`，但**会带上 `static/`**（POI 图片必须传，否则小程序裂图）。

## 3. 数据库：把本地的 308 条 POI 迁过去

**不要用 `init_db.py`**——它会清库重建成最早的 88 条。正确做法是导出再导入：

```powershell
# Windows 本地（把路径换成你的 mysqldump.exe）
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqldump.exe" `
  -uroot -p --default-character-set=utf8mb4 --single-transaction `
  travel > travel.sql
scp travel.sql root@1.2.3.4:/root/travel.sql
```

```bash
# 服务器上
cd /srv/travel
DB_PASS='换成强密码' bash deploy/scripts/bootstrap_db.sh /root/travel.sql
```

然后把 `/srv/travel/travel-api/.env` 里的库账号改成最小权限账号：

```ini
DB_USER=travel_app
DB_PASSWORD=同上强密码
```

## 4. 后端配置 `.env`

```bash
cp /srv/travel/deploy/env/.env.prod.example /srv/travel/travel-api/.env
chmod 600 /srv/travel/travel-api/.env
nano /srv/travel/travel-api/.env
```

必须改的项（对照 `preflight_release.py` 的 FAIL 项）：

| 变量 | 值 |
|---|---|
| `APP_ENV` | `prod` |
| `MOCK_LOGIN` | `false` |
| `WECHAT_APPID` / `WECHAT_SECRET` | 微信公众平台真实凭据 |
| `JWT_SECRET` | `openssl rand -hex 32` 重新生成 |
| `CORS_ORIGINS` | `https://www.你的域名,https://admin.你的域名` |
| `PUBLIC_API_ORIGIN` | `https://api.你的域名` |
| `PORTAL_ORIGIN` / `ADMIN_ORIGIN` | `https://www.…` / `https://admin.…` |
| `CDN_ORIGIN` | `https://api.你的域名`（图片同域时） |
| `ICP_NO` | 你的备案号 |
| `PRIVACY_CONTACT` | 你的邮箱 |
| `ADMIN_BOOTSTRAP_PASSWORD` | 强密码（首次启动建管理员用） |
| `FEATURE_QA_CHAT` | `true`（想用问答）；`LLM_API_KEY` 填你的 key |

## 5. 起服务

```bash
# systemd 单元
sudo cp /srv/travel/deploy/systemd/travel-api.service /etc/systemd/system/
sudo chown -R travel:travel /srv/travel
sudo -u travel bash /srv/travel/deploy/scripts/deploy.sh
sudo systemctl status travel-api --no-pager
curl http://127.0.0.1:8000/api/v1/health
```

## 6. Nginx + HTTPS

```bash
# 先把模板里的 example.cn 全部换成你的域名
sed -i 's/example\.cn/你的域名/g' /srv/travel/deploy/nginx/travel.conf.example
cp /srv/travel/deploy/nginx/travel.conf.example /etc/nginx/conf.d/travel.conf

# 先只放 80，签证书（certbot 需要 80 可达）
# 如模板里 443 段证书还不存在，先用 --nginx 或临时注释 443 段
apt -y install certbot python3-certbot-nginx
certbot --nginx -d api.你的域名 -d www.你的域名 -d admin.你的域名 --agree-tos -m 你的邮箱

nginx -t && systemctl reload nginx
curl -I https://api.你的域名/api/v1/health
```

## 7. 小程序：只改一处域名 + 换 AppID

1. `travel-miniapp/utils/config.js` 顶部：

```js
const PROD_DOMAIN = 'api.你的域名';   // ← 只改这一行
const CDN_DOMAIN  = '';              // 图片同域就留空
```

2. `travel-miniapp/project.config.json` 的 `appid` 换成你的真实 AppID（`project.private.config.json` 里那份是测试号，不会上传）。

3. 开发者工具「上传」→ 微信公众平台「版本管理」→ 设为**体验版** → 手机扫码验证。

---

## 8. 微信公众平台要配的东西

| 位置 | 填什么 |
|---|---|
| 开发管理 → 开发设置 → **服务器域名** | request：`https://api.你的域名`；downloadFile：`https://api.你的域名` |
| 设置 → 基本设置 → **服务类目** | 旅游 → 旅游信息查询 |
| 设置 → **用户隐私保护指引** | 按 `travel-miniapp/pages/privacy` 的内容填写并发布 |
| 版本管理 | 上传体验版 → 自测 → 提交审核 → 发布 |

> 域名必须**已备案 + HTTPS + 已在服务器域名里登记**，否则正式版一切请求都会失败（就是你截图里那种网络异常）。

## 10. 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 体验版仍报网络异常 | 域名没备案 / 没进白名单 / 用的是 IP | 三处必须一致：备案、证书、微信后台 |
| 图片 404 | `static/` 没上传，或 Nginx 没配 `/static` | 检查 `upload.ps1` 是否带上 static |
| 管理端打不开 | 只在 admin 子域开放；或证书没覆盖该子域 | 证书 SAN 要含 `admin.你的域名` |
| 登录失败 | `MOCK_LOGIN` 还是 true，或 AppSecret 不对 | 改 `.env` 后 `systemctl restart travel-api` |
| 提交审核被拒 | 类目/隐私指引/文案含"预订、下单、购买" | 跑 `preflight_release.py`，红线词扫描是 PASS 才提交 |
